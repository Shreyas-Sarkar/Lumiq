# Domain documentation

One product context covers both frontend and backend.

- Root `GLOSSARY.md` holds conceptual vocabulary; implementation belongs in
  `CONTEXT.md`.
- Read relevant `docs/adr/` decisions before reopening a choice.
- Record consequential accepted choices with alternatives and tradeoffs.
  Mark proposals as proposed, never accepted merely because they were suggested.
- Use the installed `domain-modeling` formats when editing domain documents.
- Keep current implementation, limitations, and future specs distinct.
